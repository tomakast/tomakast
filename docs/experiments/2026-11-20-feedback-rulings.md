## sheet parity rulings
Ruling: search and sheets already share one engine path (parser + evaluator, the same `Context` from `with_context` for search, pad push, pad update, open-pad refresh and Copy Last Result); a 128-row corpus (`plugins/calc/src/sheet_parity.rs`) pins that every search answer is the sheet's answer and every bare value search hides shows in a sheet — if wrong, the test names the row.
Ruling: a percentage kept in a variable or `prev` is still a percentage (`tax = 13%`, `salary - tax` is `salary - 13%`; `tax of 5000 usd` works) — the evaluator read only the syntax, so a sheet gave `cannot subtract USD and a number` where the one-line query answers — cost: `x = 15%` then `80 + x` is now 92, was 80.15.
Ruling: `t` is no longer a reserved name (19 stay reserved): `t = 2 h` and `speed * t` work; `3 t` is still three tonnes, `t` alone with no variable still says it is a unit — the brief's own sheet uses `t` — if wrong, re-add it to `units::reserved`.
Ruling: a product or quotient of length, time, area, volume and speed is a unit of the dimension it makes (`10 km / 2 h` = 5 km/h, `90 km/h * 2 h` = 180 km, `100 km / 50 km/h` = 2 h, `2 m * 3 m` = 6 m2, `cm2 * cm` = ml), in the unit whose size it has, else the base unit (m, s, m2, l, m/s); in search and sheets alike — mass, data, angle, temperature and currency still refuse — cost: `1000 l / 2 m2` reads `500 mm`.
Ruling: left as is — a variable holds the value its line shows: `d = 18 nov` then `days until d` is -1 days (the one-line `days until 18 nov` rolls to next year, 364 days), and `today` then `prev in Tokyo` keeps Moscow's date (as `x = today`, `x in Tokyo` already did); `sum`/`total` do not exist (only `prev`/`ans`) and were not added.
