# Home Part 2: the edit mode — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An edit mode for Home, fully usable by keyboard and also by mouse, that moves, removes, resizes and restores Home tiles and writes every change to `config.toml` at once.

**Architecture:** The core gains what the mode needs: an edit that hands back what it removed (so an undo restores the file byte for byte), a map from a Home tile to its entry's index, the widget's sizes, and a re-read of the file when the watcher reports a change. A built-in module adds the "Edit Home" command through an internal effect. The UI decides the mode's keys as a pure function, like the strip's (`strip/keys.rs`). The mode itself lives in new files, `strip/edit.rs` (pure) and `launcher_view/home_edit.rs` (applying it). It has its own focus handle and key context, so the search field never sees a key while the mode lasts.

**Tech Stack:** Rust 2024, GPUI via `gpui-kit =0.10.0` (pinned `gpui-pre 0.3.12`), `toml_edit`, `ashpd` (Linux portal).

**Spec:** `docs/superpowers/specs/2026-11-21-home-widgets-design.md`, section "Part 2: The edit mode". Part 1 is done (`docs/superpowers/plans/2026-11-21-home-part1.md`); its ledger of rulings and deferred minors is in the shared notes folder as `home-part1-ledger.md`.

## Rulings on Part 1's open questions

1. **A removed entry's comment lines are returned, and the undo puts them back.** `HomeEdit::Remove` hands back a `Removed { at, entry, comments }`, and `Removed::undo()` is `HomeEdit::Insert { at, entry, comments }`. "Comments" means the comment lines right above the entry; comments *inside* its table body travel with the table. Remove followed by its undo gives the file back byte for byte.
   - *Corrected in execution:* the undo writes the entry back in the launcher's own form (`widget`, then `size`, then its string parameters) with its comment lines above it. Comments inside its table body are not kept, and an entry written in another form comes back in that form. Remove followed by undo gives the file back byte for byte only for an entry already in the launcher's form with no comment in its body (see `Removed` in `crates/core/src/home_file.rs` and the acceptance doc's known gaps).
   - Handing the comment to the next entry was rejected: `Insert(i)` lands above entry `i`'s own comment lines, so the restored entry would end up above its own comment, and the next entry would be mislabelled.
   - A comment lost when the user leaves without undoing is the comment of the entry they removed. A blank-line-separated comment, the entry's "place", is still handed on as today.
2. **Inline arrays, Remove(0):** the next element takes the removed one's place and indent, never its comments, which go into `Removed.comments`.
3. **CRLF:** if every `\n` of the file is part of a `\r\n`, the written file uses `\r\n` everywhere. A file with mixed line endings is written as edited.
4. **The write stays on the UI thread, with its fsync.** It took 1–2 ms on this machine's NVMe btrfs (median 1.1 ms, max 2.4 ms over 30 runs). The list the write returns is what keeps the indices and the `Changed` check coherent. One write per user action: a drag writes once, on drop. Held repeats of Delete/Backspace and Ctrl/Cmd+Z are ignored, so one press removes or restores one tile; held arrows still repeat. (*Corrected in execution:* held Enter, Esc and Ctrl/Cmd+K are ignored too, so a key still held from the press that entered the mode neither leaves it nor opens the menu.) A write over 16 ms is logged at `warn` with its duration.

## Other rulings

- **The launcher's own write comes back from the watcher.** The plugin manager reads `config.toml` off the UI thread and posts `ManagerAction::Home(list)`. If that list was read before the launcher's next write, applying it would undo that write, and the next edit would be refused with `Changed`. The core therefore re-reads the file when the action arrives (`Core::home_file_changed`) and ignores the list carried in the action, unless it has no config file.
- **Selection is kept by Home index.** The strip leaves out entries that cannot show (plugin not running) and tiles the paint guard stopped, and `Slot::Home(n)` renumbers identical tiles after a move. So the mode keeps the selected entry's index in `core.home()`, and maps it to a strip position each time. "Move one place" jumps to the next *visible* tile's index.
- **"Edit Home" is an internal effect.** `Effect::EditHome` is honoured only in a reply to a request of the open window, like `SetRootQuery`; a plugin cannot send it. It comes from a built-in module, `modules/home`, provider id `home`, whose one item is the "Edit Home" command. The host also refuses a plugin action titled "Edit Home", as it does for "Add to Home".
- **The empty-Home check** happens after the query is cleared: Home is empty when the strip at the empty query has no tile, even if `config.toml` has entries that cannot show now.
- **Right-click on any strip tile** selects it and opens its Ctrl/Cmd+K panel: for a Home tile it ends with "Edit Home", for a search tile with "Add to Home". In the mode, right-click opens the tile menu.
- **Leaving the mode:** the strip selection goes to the tile that was selected (`Focus::Strip { tile, part: None }`), or to the list when Home is now empty.
- **Reduced motion:** `tomakast_platform::reduced_motion() -> Option<bool>`, read off the UI thread each time the mode is entered.
  - The env var `TOMAKAST_REDUCED_MOTION` (`1` or `0`) wins.
  - On Linux, KDE's `kdeglobals` `[KDE] AnimationDurationFactor=0` means reduced. So does the portal's `org.gnome.desktop.interface` `enable-animations` = false, read through ashpd `Settings`.
  - Elsewhere, or when it cannot be read, the value is `None`, and the tiles jiggle. Not done: macOS and Windows reading. It is listed in the final report.
- **Toast kinds:**
  - "Home is empty…" is an error toast: the command did nothing.
  - "Press [Ctrl] [Z] to restore widget" is a success toast with a 5 s TTL (`theme::UNDO_TOAST_TTL`).
  - Write failures use Part 1's error toasts. `Changed` shows its own text, "config.toml changed: try again".

## Review Focus

1. **An entry that cannot show sits between visible tiles,** for example a disabled plugin's tile in the middle of the file. Shift+→ must still pass the next visible tile, and its undo must land at the old index. Tests: Task 2 (`home_index`) and Task 4 (`move_skips_entries_that_do_not_show`).
2. **Two identical tiles.** Removing the second of two identical entries must remove the second, not the first. Tests: Task 2 (`identical_tiles_map_to_their_own_entries`) and Task 6 (`removing_the_second_of_two_identical_tiles_removes_it`).
3. **The file was edited by hand while the mode is open.** The edit is refused with `Changed`, a toast says so, and the strip shows the file's list once the watcher's re-read applies it. An undo refused this way keeps its entry on the stack. Tests: Task 6 (`an_edit_of_a_changed_file_is_refused_and_keeps_the_undo`).
4. **A stray key does nothing outside the mode's keys.** A letter, a digit, Space, ↑ or ↓ neither leaves the mode, nor types into the field, nor reaches a tile. Tests: Task 6 (`typing_in_the_mode_does_nothing`).
5. **Removing every tile, then leaving.** The strip goes, and nothing panics on an empty selection. Undo after removing the last tile brings it back while the mode lasts. Tests: Task 6 (`removing_the_last_tile_then_leaving_removes_the_strip`).

  impl ToastBar { pub(crate) fn show_keys(&mut self, kind: ToastKind, parts: Vec<ToastPart>, cx); }

**Behaviour to build:**
- **Getting in by keyboard:**
  - A Home tile's Ctrl/Cmd+K panel ends with "Edit Home". `selection()` returns one for every Home tile, even one without frame actions, so the panel opens and the footer shows the hint.
  - Choosing "Edit Home" enters the mode with that tile selected.
  - `edit_home_command` does three things: `set_root_query("")`; it reads the strip; then, if the strip is empty, it shows the error toast `Home is empty: add widgets from the search`, else it enters with the first tile selected.
- **While in the mode (no panel open):**
  - The root key context is `HomeEdit` only, so no launcher binding fires, and the mode's focus handle has the keyboard.
  - The strip row's `on_key_down` sends every key to `home_edit_key`. That maps it with `edit_key_of`, applies `edit_step`, and always stops propagation.
  - `shortcut_key` returns at once while the mode lasts.
  - The header content draws at `opacity(0.4)`.
- **Writes:**
  - `apply_home_edit` calls `core.edit_home`. A `Removed` is pushed to the undo stack, followed by the toast `Press` [Ctrl] [Z] `to restore widget`, whose chips are `chrome::key_chip` and labelled ⌘ on macOS.
  - The selection after the edit:
    - after a Move: its `to`;
    - after a Remove: the same Home index, which `selected_position` resolves to the next tile, else the last;
    - after an undo: its `at`.
  - Errors use Part 1's toasts (`Broken` → the broken-file copy; others → `e.to_string()`).
- **Undo:** `pop` the stack, then `edit_home(removed.undo(home.len()))`. On error, push it back and toast.
- **The menu:**
  - Ctrl/Cmd+K opens the panel with target `HomeEdit(index)`. Its entries are the sizes from `core.widget_sizes` when there is more than one, with the strip tile's size marked current, then `Remove`.
  - The current entry shows a trailing check mark, element id `action-current:{ix}`, aria "Current size".
  - Enter on a size gives `Resize` (choosing the current size closes the panel and changes nothing). Enter on Remove removes.
  - Esc and Enter close the panel back into the mode: `close_panel` focuses the mode's handle while the mode lasts.
- **Leaving:** Esc or Enter (no panel open), and `close_all` (the launcher hiding). The undo stack is dropped. The strip focus goes to the selected tile, or to the list when Home is empty. The field takes the keyboard back.
- **No events to tiles:**
  - `click_tile` and `press_button` do nothing in the mode.
  - `visible_tiles` reports `focused: None` and `pointer: None` for every tile.
  - `send_pointer` sends nothing.
  - Each tile gets an occluding overlay, so its buttons and canvases take no hover or press.
  - Tiles still tick and draw.
- **Drawing:**
  - Each tile shifts by `wobble(ix, now - started)`, with `relative()` and `.left()/.top()`, which keeps the layout. `window.request_animation_frame()` is called while the mode lasts and motion is not reduced.
  - The selected tile has the focus ring.
  - A ⊖ badge sits in each tile's top-left corner: the bundled Lucide `circle-minus`, or a drawn circle if the bundle lacks it. Its element id is `home-edit-remove:{tile_name}`, role Button, aria `Remove {title}`. It is clickable in Task 6.
  - The footer context reads `Edit Home`, the primary hint `Done`, and the Ctrl/Cmd+K hint is shown.

  - `tomakast_platform::reduced_motion() -> Option<bool>` (blocking; call it off the UI thread). Its pure parts are `fn kde_reduced(kdeglobals: &str) -> Option<bool>` and `fn env_reduced(value: Option<&str>) -> Option<bool>`.
  - `pub(crate) struct Drag { from: usize /*strip position*/, start_x: f32, x: f32 }`.

**Behaviour to build:**
- **Right-click** on a strip tile (outside the mode) moves the strip focus to it and opens its panel. In the mode, it selects the tile and opens the tile menu.
- **Long press:**
  - A left press on a Home tile, outside the mode, starts a 500 ms timer task. It is cancelled by a release, by a move of more than 4 px, or by the launcher hiding.
  - When it fires, the mode is entered with that tile selected.
  - The release that follows clicks nothing: a `suppress_click` flag is checked in `click_tile` and `press_button` and cleared on the next press.
- **⊖ click** removes that tile, as Delete does, with the same toast and undo.
- **Drag:**
  - In the mode, a press on a tile followed by a move of more than 4 px starts a `Drag`. The dragged tile draws at the pointer's x offset, above the others.
  - On release, `drop_position(slots, content_x)` gives the strip position `q`. If `q != from`, apply one `Move { from: indices[from], to: indices[q] }`; that is the only write.
  - Within 24 px of the strip's edge the strip scrolls 8 px per frame.
- **A click outside the tiles leaves:**
  - In the mode, an occluding layer covers the header and the list, and a mouse down on it leaves the mode and does nothing else.
  - The strip's own background, outside the tiles, also leaves.
  - A tile's mouse down stops propagation.
- **Reduced motion:**
  - `enter_home_edit` spawns `reduced_motion()` on the background executor and sets `reduced_motion` when it answers (`Some(true)` means reduced).
  - When reduced, nothing jiggles and no animation frame is requested. Each tile gets a dashed outline (`border_dashed()`, `palette.text.alpha(0.5)`) instead.
  - `TOMAKAST_REDUCED_MOTION=1` forces it (used by the test).
