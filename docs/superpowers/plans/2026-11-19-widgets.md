# Widgets (tiles in the root view) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins and built-in modules draw tiles that the core places in a horizontal strip between the search field and the root list. The tiles are "always" tiles and query-condition tiles. They are interactive, live up to 60 fps while on screen, and free to draw on a canvas of native commands plus an SVG layer. Calc's search answer becomes one double-width tile.

**Architecture:**
- **Contract.** WIT 0.1 is edited in place.
  - `search` answers a `search-answer` (items plus widget answers).
  - A new export, `render-widget(id, context) -> widget-frame`, returns a flat node list with parent indices.
  - Three new effects and one new event.
- **Core.**
  - `tomakast-core` holds the GPUI-free model (`widget.rs`: frames, checks) and the strip state (`strip.rs`: always set, condition answers, cached frames, images, order, the render scheduler).
  - Every widget call runs on the module's worker, like `search`. The UI thread never waits.
  - The core keeps the frames across window instances: the window is rebuilt on every show, so the cache cannot live in the view.
- **UI.** `tomakast-ui` lays out the strip and maps frames to GPUI elements. A custom element paints the canvas commands. The UI rasterizes SVG with `usvg`/`resvg` `=0.46.0` directly, with a resolver that refuses every external reference: GPUI's own `SvgRenderer` reads `href` paths from disk.
- **Frame clock.** The UI drives it with `window.request_animation_frame()` only while a visible tile is dirty, animating or in flight. When the window is hidden it is closed, so nothing ticks and nothing renders.

**Tech Stack:** Rust 2024 and wasmtime 50 (component model, epoch deadlines). The guest SDK uses `wit-bindgen`. GPUI comes from `gpui-pre 0.3.12` through `gpui-kit 0.10.0`. The UI also uses `gpui-component 0.10.0` (`Scrollbar`, `ScrollbarMode::Scrolling`), and `usvg`, `resvg` and `image` at their in-tree versions. `roxmltree =0.21.2` (in-tree) checks SVG in the host.

**Spec:** `docs/superpowers/specs/2026-11-19-widgets-design.md` (approved; its "Decided by the user" and "my call" lines are settled). Also read:
- `docs/superpowers/specs/2026-11-18-tomakast-core-design.md` (UI model A, anti-goals, budgets: warm open ~50 ms, ~0% CPU hidden);
- `docs/superpowers/specs/2026-11-19-query-history-design.md` (the ↑ rule).

## Global Constraints

- **The contract is edited in place** (the user's ruling). WIT 0.1 is edited in place: no `since_v0.2.0`. `FROZEN` is re-hashed once, and `FROZEN.md` records "edited in place: widgets, 2026-11-19, no consumers yet". Plugin-facing types stay GPUI-free; GPUI stays inside `tomakast-ui`.
- **The WIT has no recursive types.** A frame is a flat `list<node>`: node 0 is the root (`parent: none`), and every other node names an earlier node as its parent.
- **The UI thread never waits on a plugin.** Every render runs on the module worker. A frame for an older request is dropped, and the last frame stays on screen.
- **Rate.** At most **60 renders per second per tile**. A `redraw-widget` beyond that is merged into the next frame. Nothing renders while a tile is off screen or the launcher is hidden.
- **`render-widget` deadlines:**
  - **soft: 16 ms**, measured on the worker around the call only, not the queue wait. A late frame is dropped. **5 consecutive** late or failed frames stop that widget for the module instance, with an error toast and a log line;
  - **hard: 100 ms**, the epoch interrupt (100–110 ms with the 5 ms tick). Past it the plugin is broken, by the existing rule.
- **Render calls** count against no background budget. The 30/s cap on unsolicited view updates does not apply to them.
- **Caps** (host and core constants, also in WIT doc comments):
  - 16 widgets per plugin;
  - 16 widget answers per `search`, payload ≤ 4 KiB;
  - per frame: 256 nodes, node nesting ≤ 32, 10 000 canvas commands plus path segments, 1 MiB (`frame_bytes`), nesting of clips and transforms ≤ 32;
  - images: ≤ 2 MiB each, SVG ≤ 512 KiB, ≤ 64 images and ≤ 8 MiB in total per plugin;
  - SVG: ≤ 4096 elements, ≤ 32 filter primitives. A filter region transformed to device pixels may be at most 2× the raster's width and height. A raster that takes > 16 ms refuses the document from then on.
- **Strip look:**
  - tile height **120 px** (three 40 px rows), gap **8 px**, side margin `EDGE_PADDING` (16 px), 8 px above and below the strip;
  - with the panel 750 px wide, content `W = 718`, a single tile is `(W - 8) / 2 = 355`, a double tile is `718`;
  - the scroll viewport spans the full panel width, so the next tile peeks in the right margin. The same happens at the left edge once the strip is scrolled;
  - the scrollbar is a `gpui-component` overlay in `ScrollbarMode::Scrolling`. There is no source label on tiles;
  - the core draws each tile's frame, rounded corners (10 px) and focus ring (2 px).
- **Security:**
  - tiles are clipped to their frame;
  - no core prompt ever appears inside the strip;
  - tile texts follow the plugin-string rules: ids follow the id rule, labels are one line ≤ 1 KiB, text nodes are ≤ 4 KiB and may contain `\n` but no other control characters;
  - adding a widget or renaming its title asks for approval again.
- **Permissions.** Showing tiles needs none. Condition tiles come from `search`, which needs `search`. User actions are `action`, `key`, and a completed click: a pointer `up` on the node that got the last `down` (a press alone is not one). Only these allow `copy-text`, `open` and `push-view`/`close-window` as in answer to `run`.
- **CI commands** (every task ends green on all of them it touches):
  - `cargo fmt --check`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo clippy -p tomakast-plugin-host --lib -- -D warnings`;
  - `cargo test --workspace`;
  - guests with `CARGO_TARGET_DIR=target/plugins`: `cargo {fmt --check,clippy --all-targets [--target wasm32-wasip2] -- -D warnings,test} --manifest-path {crates/plugin-sdk,plugins/calc,plugins/kitchen-sink}/Cargo.toml` (calc's test runs with `--release`).
- **Commits.** Commit only the files of the task, by path. Never `git add -A` and never stash. Plans and docs are in English.

## Review Focus

- **A plugin reloaded or broken while its tile is on screen.** The tile leaves the strip at once. Enter and Ctrl+K never reach the new instance with the old payload. Test `a_broken_or_reloaded_plugins_tiles_leave_the_strip` in Task 7.
- **Fast typing with calc** (`2+2`, then `2+23`, then Enter within a few ms). Enter and Ctrl+K never act on a tile answered for an older query than the field's. With a search in flight, Enter waits for the answer and the new tile's first frame, at most 116 ms (`DYNAMIC_SEARCH_DEADLINE` + `SOFT_RENDER_DEADLINE`). Then it acts on what is on screen, or else on the list's first row as today. Test `enter_waits_for_the_new_answer_and_never_acts_on_an_older_one` in Task 12.
- **A theme switch or a scale change while the launcher is open.** Every visible tile renders again with the new context. An SVG is rasterized again at the new scale, and a stale raster is never stretched. Tests `an_env_change_redraws_visible_tiles` (Task 7) and `svg_raster_is_keyed_by_device_size` (Task 11).
- **Hostile or long tile text** (1 KiB without spaces, RTL overrides, `\n` in canvas text, emoji runs). It stays inside its tile and never pushes the strip or the list. Test `tile_text_never_leaves_the_tile` in Task 9.
- **Many tiles** (16 plugins × 16 always tiles). The open stays a plain layout of cached frames. Only the on-screen tiles and the peeking one are rendered. Test `only_visible_tiles_render_among_two_hundred` in Task 7.

`check_frame` rules:
- node 0 has `parent: None`. Every other node has `Some(p)` with `p` less than its own index, and node `p` is a `Row`, `Column` or `Overlay`.
- `Button` and focusable `Canvas` nodes need a non-empty `id`. Non-empty ids are unique.
- Every `f32` is finite. Sizes, widths, heights, radii, `rx`/`ry`, `gap`, padding, `grow`, `stroke` and font `size` are ≥ 0. `opacity`, `Progress` and `ColorStop.at` are in `0..=1`. A text `size` is in `1..=200`. A `Transform.scale` component is in `0.001..=100`.
- `PushClip`/`PopClip` and `PushTransform`/`PopTransform` are balanced inside each canvas, never cross each other, and nest ≤ 32 deep.
- At most 256 nodes, 10 000 commands plus segments over all canvases, and `frame_bytes ≤ MAX_FRAME_BYTES`.

The WIT additions to `interface types`, with these shapes and these caps in their doc comments:

```wit
  /// A tile `search` shows for its query. `id` names a `[[widgets]]` entry of plugin.toml;
  /// `payload` (at most 4 KiB) comes back in the tile's events and render contexts; `actions`
  /// work as an item's (at most 16; the first is Enter's), and act with this payload.
  record widget-answer { id: string, payload: string, actions: list<action> }
  /// At most 50 items and 16 widget answers; a longer answer is rejected as a whole.
  record search-answer { items: list<item>, widgets: list<widget-answer> }

  enum color-token { text, muted, panel, border, selected, error, success }
  /// A theme colour, or `0xRRGGBBAA`.
  variant color { token(color-token), rgba(u32) }
  record theme-colors { text: u32, muted: u32, panel: u32, border: u32, selected: u32, error: u32, success: u32 }
  record text-sizes { title: f32, value: f32, body: f32, caption: f32 }
  record widget-theme { dark: bool, colors: theme-colors, ui-font: string, mono-font: string, sizes: text-sizes }
  record point { x: f32, y: f32 }
  /// The pointer over the tile, in the tile's logical pixels; `node-id` is the canvas under it.
  record pointer-at { node-id: option<string>, at: point }
  /// What `render-widget` is told. `millis-shown` counts from when the tile came on screen.
  /// `query` and `payload` are set for a condition tile.
  record widget-context {
    width: f32, height: f32, scale: f32, theme: widget-theme, millis-shown: u64,
    focused: option<string>, pointer: option<pointer-at>, query: option<string>, payload: option<string>,
  }

  record edges { top: f32, right: f32, bottom: f32, left: f32 }
  enum align { start, center, end, stretch }
  enum justify { start, center, end, space-between }
  record layout { padding: edges, gap: f32, align: align, justify: justify }
  enum text-style { title, value, body, caption }
  enum text-align { start, center, end }
  /// `text` is at most 4 KiB and may hold line breaks (no other control characters);
  /// `max-lines` 0 means 1.
  record text-node { text: string, style: text-style, color: color, align: text-align, max-lines: u8, mono: bool }
  record icon-node { icon: icon, size: f32 }
  enum image-fit { contain, cover, fill }
  record image-node { image: string, fit: image-fit, radius: f32 }
  /// Focusable; pressing it sends `widget-event.action` with `action-id`.
  record button-node { label: option<string>, icon: option<icon>, action-id: string }
  record canvas-node { focusable: bool, commands: list<draw> }
  variant node-kind {
    row(layout), column(layout), overlay(layout), text(text-node), icon(icon-node),
    image(image-node), progress(f32), spacer, button(button-node), canvas(canvas-node),
  }
  /// Node 0 is the root (`parent: none`); every other node names an earlier row, column
  /// or overlay. `width`/`height` fix the size in logical pixels; `grow` shares free space.
  record node { id: string, parent: option<u32>, grow: f32, width: option<f32>, height: option<f32>, kind: node-kind }

  record color-stop { color: color, at: f32 }
  /// Two stops only; `angle` in degrees, 0 is up, clockwise (CSS).
  record linear-gradient { angle: f32, start: color-stop, end: color-stop }
  variant paint { solid(color), linear(linear-gradient) }
  /// Filled when `stroke` is none, else stroked that wide. `opacity` multiplies the paint.
  record shape-style { paint: paint, stroke: option<f32>, opacity: f32 }
  record rect-cmd { x: f32, y: f32, width: f32, height: f32, radius: f32, style: shape-style }
  record ellipse-cmd { cx: f32, cy: f32, rx: f32, ry: f32, style: shape-style }
  record quad-to { ctrl: point, to: point }
  record cubic-to { ctrl-a: point, ctrl-b: point, to: point }
  variant path-segment { move-to(point), line-to(point), quad-to(quad-to), cubic-to(cubic-to), close }
  record path-cmd { segments: list<path-segment>, style: shape-style }
  /// One line, at most 1 KiB; `x`/`y` is the top-left of its line box. `font` none: the theme's
  /// UI font (`mono`: its monospace font).
  record text-cmd { x: f32, y: f32, text: string, size: f32, color: color, font: option<string>, mono: bool, opacity: f32 }
  record image-cmd { image: string, x: f32, y: f32, width: f32, height: f32, opacity: f32 }
  record clip-rect { x: f32, y: f32, width: f32, height: f32 }
  /// Applied as scale, then rotate (degrees, clockwise), then translate. Shapes and paths take
  /// all of it; text, images and SVG take only the translation and the scale. A clip under a
  /// rotation clips the axis-aligned box around the rotated rectangle.
  record transform { translate: point, scale: point, rotate: f32 }
  variant draw {
    rect(rect-cmd), ellipse(ellipse-cmd), path(path-cmd), text(text-cmd), image(image-cmd),
    svg(image-cmd), push-clip(clip-rect), pop-clip, push-transform(transform), pop-transform,
  }

  /// are an "always" tile's (a condition tile's come from its answer). `animate`: render
  /// again on the next frame. A frame that breaks a cap is dropped and logged.
```

  - The answer is converted, then checked with `tomakast_core::check_frame`, `check_frame_text` and the images. A failure is an `Err` for this frame: the plugin lives on, and the failure is logged at most once per 10 s per widget.
  - Frame images pass `check_image` and the budget, then reach the core.
  - The recorder notes `export render-widget`, plus `node-kind <case>`, `draw <case>`, `path-segment <case>`, `paint <case>` and `color <case>` for what the frame holds (the WIT type names, as `wit_names()` spells them). `check_image` notes `image-format <case>`.
- **`search`**: `check_answers` requires declared ids, ≤ 16 answers, payload ≤ 4 KiB and valid actions. A failed check rejects the whole answer (items too), with the denial toast, as today's item cap does.
- **`on_widget_event`**:
  - `Action` and `Key` are user actions (`StartedBy::User`, `Origin::Answer`);
  - `Pointer(Down)` is not a user action; the host records `(widget, node)` as pressed;
  - `Pointer(Up)` on the pressed node completes a click: it is a user action, and it clears the press;
  - every other event is `StartedBy::Host` and `Origin::Unsolicited`.
  - The recorder notes `event widget` and `widget-event <case>`, `pointer-kind <case>`.
- **`check_effects`** gains `widgets: &[WidgetDecl]`:
  - `show-widgets` ids are declared, unique and ≤ 16, else the whole answer is rejected;
  - `redraw-widget` names a declared id, else the whole answer is rejected;
  - `set-widget-image` passes `check_image` and the budget;
  - unsolicited `show-widgets` and `set-widget-image` share `Rates.widgets` (30 per s); beyond that they are dropped with a denial;
  - `redraw-widget` is never rate-counted (the core merges it).
- **`check_frame_text`**:
  - node ids follow the id rule;
  - `text-node.text` is ≤ 4 KiB, with no control characters but `\n`;
  - button labels follow the label rule; `text-cmd.text` is a label (≤ 1 KiB, one line);
  - `font` follows the id rule; icons follow the existing icon checks; `actions` follow the existing action checks;
  - `image-node.image` and `image-cmd.image` ids follow the id rule.
- **`check_image`**:
  - PNG starts with `\x89PNG\r\n\x1a\n`; JPEG starts with `FF D8`; format and bytes agree;
  - PNG/JPEG ≤ 2 MiB, SVG ≤ 512 KiB (UTF-8).
- **`check_svg`** (roxmltree):
  - it parses, and has ≤ 4096 elements and ≤ 32 elements whose name starts with `fe`;
  - no `script` or `foreignObject` element;
  - every `href`/`xlink:href` starts with `#`, `data:image/png;base64,` or `data:image/jpeg;base64,`;
  - no attribute or `<style>` text has `url(` other than `url(#`, and none has `@import`.
- **`ImageBudget`**: ≤ 64 ids and ≤ 8 MiB summed. Replacing an id frees its old bytes first.

  - `StripTile { key: WidgetKey, title: String, size: WidgetSize, frame: Option<Arc<Frame>>, condition: Option<ConditionTile> }`, with `ConditionTile { payload: String, actions: Vec<Action>, stale: bool }`;
  - `Core::strip(&self, now: Instant) -> Vec<StripTile>`;
  - `VisibleTile { key: WidgetKey, focused: Option<String>, pointer: Option<PointerAt> }`;

  - `Core::widget_actions(&self, key: &WidgetKey) -> Vec<Action>`: the condition answer's actions, else the last frame's; empty for a stale tile;
  - `Core::widget_answers_pending(&self) -> bool`: some started dynamic provider that declared widgets has not yet sent `WidgetAnswers` for the current generation.

Rules:
- **Order.**
  - The condition tiles come first: providers by id, each in its answer order. A tile shows only once its first frame arrived (atomic swap).
  - Then the always tiles: first those listed in `order`, in that order. The rest follow by `approved_at`: `None` (built-ins) first, then ascending, ties by provider id, then by the module's declared order.
  - `hidden` removes a tile from both groups.
  - An always tile that is also answered shows once, in the condition group.
- **New generation** (the spec's atomic swap). `Core::search` marks every condition tile `stale`: it may stay on screen, with its own frame, but it is not actionable (coordinator's ruling): `send_widget_event` refuses `Action`, `Key` and `Pointer` on a stale tile with `Err("answered for an older query")`. A provider's `WidgetAnswers` for the current generation replace all its condition tiles at once: the answered ones with an `Ok` on-time frame show; the rest go. There is no timeout. Every search ends in a `WidgetAnswers`, including a failed one (Task 5), a superseded search is followed by a newer one, and a stuck worker is broken at 100 ms, which drops its tiles. An answer for an older generation is dropped.
- **Tick.**
  - `widget_tick` diffs `visible` against the shown set: it sends `Shown` (and records `shown_at`) or `Hidden` events (`request: None`), and marks newly shown tiles dirty.
  - It renders a visible tile when all of these hold:
    - it is dirty, or its last frame had `animate`;
    - it has no render in flight;
    - at least `MIN_RENDER_INTERVAL` passed since its last issue;
    - it is not stopped.
  - The context is the decl size from `env`, `millis_shown = now - shown_at`, `focused`, `pointer`, plus the query and payload for a condition tile.
  - It returns true while any visible tile is dirty, animating or in flight.
  - A `set_widget_env` that differs from the last one marks every visible tile dirty.
- **`widgets_hidden`** sends `Hidden` for every shown tile and clears the shown set. With no tick afterwards nothing renders. A `redraw-widget` or an `animate` frame while hidden only marks dirty.
- **Logs.** Every render issue is logged at `trace!(target: "widgets", provider, widget, "render")`, for the acceptance count.

### Task 10: The native canvas

**Files:**
- Create: `crates/ui/src/strip/canvas.rs`
- Modify: `crates/ui/src/strip/components.rs`, `crates/ui/tests/strip.rs`

**Interfaces:**

- Produces:
  - `canvas::Affine { a, b, c, d, e, f: f32 }`, with `identity()`, `from(&Transform)` (scale, then rotate clockwise in degrees, then translate), `then(&self, inner: &Affine) -> Affine`, `apply(&self, Point) -> Point` and `scale_only(&self) -> (f32, f32)` (the lengths of the transformed unit vectors);
  - `canvas::PaintOp`:
    - `Quad { bounds: Bounds<Pixels>, radius: Pixels, fill: Option<Background>, border: Option<(Pixels, Hsla)> }`;
    - `Path { points: Vec<PathPoint>, fill: Option<Background>, stroke: Option<(Pixels, Background)> }`;
    - `Text { origin: Point<Pixels>, text: SharedString, size: Pixels, color: Hsla, family: SharedString }`;
    - `Image { bounds: Bounds<Pixels>, image: String, opacity: f32, svg: bool }`;
    - `Clip(Bounds<Pixels>)` and `Unclip`.
  - `canvas::plan(commands: &[Draw], origin: Point<Pixels>, theme: &WidgetTheme) -> Vec<PaintOp>`;
  - `canvas::canvas_element(key: WidgetKey, node: &Node, commands: Arc<[Draw]>, theme: WidgetTheme) -> AnyElement`.

The algorithm `plan` must follow, which its signature does not determine:
- Keep a stack of `Affine`, starting at identity, translated by `origin`.
- A `Rect` or `Ellipse` under a transform without rotation, with equal `rx`/`ry` for the ellipse, becomes a `Quad`. A circle's `radius` is `rx`. Otherwise it becomes a `Path`:
  - a rect is 4 corner arcs, each one cubic with control factor 0.5523 times the radius;
  - an ellipse is 4 cubics;
  - every point goes through the current `Affine`, so rotation is exact (cubics are affine-invariant).
- A `Path`'s `QuadTo` and `CubicTo` points are transformed the same way.
- `Text` and `Image`/`Svg` take only the translation and `scale_only()`. Text size is multiplied by the mean scale; image width and height by the x and y scale.
- A `PushClip` rect is transformed as its 4 corners. The clip is their axis-aligned box, intersected with the enclosing clip, and emitted as `Clip(..)`. `PopClip` emits `Unclip`.
- `opacity` multiplies every colour's alpha (`Hsla::opacity`, `Background::opacity`).
- A command whose transformed bounds miss the canvas bounds entirely is culled.

`CanvasElement` (a custom `Element`, like `scratchpad::AnnotationColumn`):
- `request_layout` takes the node's `width`/`height`/`grow`.
- `prepaint` runs `plan` and shapes each `Text` with `window.text_system().shape_line(..)`. For each `Image` it creates `div().opacity(o).child(img(render_image))` and runs `prepaint_as_root` at its bounds (image data comes from Task 11; until then it is skipped). `paint_image` takes no opacity and `with_element_opacity` is crate-private, but a `div`'s `opacity` style applies to its children.
- `paint` wraps everything in `with_content_mask(Some(ContentMask { bounds }))` and walks the ops recursively. A `Clip` opens a nested `with_content_mask` until its `Unclip`, because the mask is closure-scoped and the commands were balanced by `check_frame`.
  - `Quad` uses `paint_quad(quad(bounds, radius, fill, border_widths, border_color, BorderStyle::Solid))`.
  - `Path` uses `PathBuilder::fill()` or `PathBuilder::stroke(w)` (`move_to`, `line_to`, `cubic_bezier_to`, `close`), then `build()` and `paint_path(path, background)`.
  - `Text` uses `ShapedLine::paint(origin, line_height, TextAlign::Left, None, window, cx)`. Emoji glyphs ignore the text opacity (GPUI's `paint_emoji` reads only the element opacity); this is documented in the WIT text-cmd doc.
  - Prepainted image elements are painted in op order.
- A gradient is `linear_gradient(angle, linear_color_stop(c0, at0), linear_color_stop(c1, at1))`. GPUI takes exactly two stops, matching the WIT.
