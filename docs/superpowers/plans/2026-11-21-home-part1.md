# Home, Part 1: the user's own tiles, widget parameters and sizes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Home (the strip at the empty query) shows exactly the user's `[[home.widgets]]` list; plugins
declare widget parameters and sizes instead of an opaque payload and their own "always" tiles; every
search tile has the launcher's "Add to Home", which appends it to `config.toml`.

**Architecture:** The core owns Home: it reads the list from the settings, turns each entry into a
tile identified by a new `TileKey` (widget + parameters + slot), renders and caches those tiles like
the old always tiles, tells each plugin its own Home tiles (`home` event), and appends to the file
through a format-preserving writer. The contract (WIT 0.1, edited in place) swaps `payload` for
`params`, adds `size` to a widget answer, removes `show-widgets`, and adds the `home` event.

**Tech Stack:** Rust workspace, wasmtime component model (WIT), GPUI (`gpui-kit =0.10.0`),
`toml_edit` 0.25 (new direct dependency of `tomakast-core`).

**Spec:** `docs/superpowers/specs/2026-11-21-home-widgets-design.md`, Part 1. Read it first.

## Global Constraints

- Settings shape, exactly: `[[home.widgets]]` tables with `widget = "<plugin-id>/<widget-id>"`,
  optional `size` (`"quarter"`, `"single"`, `"double"`), and the widget's parameters as further
  string keys. `widget` and `size` are reserved parameter names.
- Manifest shape, exactly: `[[widgets]]` with `sizes = [...]` (first is the default; the old
  `size = "…"` accepted as a one-size shorthand; both together rejected) and `[[widgets.params]]`
  with `key` and `title`; at most 8 params per widget; all of a tile's values together at most
  4096 bytes (the old `MAX_PAYLOAD_BYTES`).
- Copy, exactly: toast "Added to Home"; toast "config.toml has an error: fix it to change Home";
  the action's title "Add to Home".
- A Home entry the launcher cannot show is not shown and never removed from the file; a size the
  widget does not offer shows the default size; an undeclared parameter is not passed to the
  plugin and stays in the file.
- `[widgets]` (order/hidden) is ignored with one warning.
- The launcher's write touches only the `home.widgets` array; it is atomic (temporary file in the
  same directory, then rename); a `config.toml` that does not parse is never written.
- No plugin can add, remove or trigger "Add to Home"; a plugin action with any id cannot reach it.
- WIT is edited in place: re-hash `crates/plugin-api/wit/since_v0.1.0/FROZEN`, add a row to
  `FROZEN.md` dated 2026-11-21.
- TDD: each behaviour gets its failing test first. Commit after each task; no attribution lines.
- The workspace builds as a whole again only at the end of Task 5: Tasks 2–4 each run their own
  crate's tests (`cargo test -p <crate>`); Task 6 runs `just check`.
- Never start a keyboard-grabbing launcher: a headless run uses its own `TOMAKAST_HOME`
  (`mktemp -d /tmp/tkw.XXXX`) with `TOMAKAST_NO_KEYBOARD=1`.

## Review Focus

1. **Two Home tiles of the same widget with different params, and two identical ones:** each
   renders, focuses and receives pointer events on its own; nothing merges (Task 2 core test,
   Task 5 UI test).
2. **A hand-edited `config.toml` with comments and other tables, then "Add to Home":** every byte
   outside `home.widgets` is unchanged (Task 1 test).
3. **`config.toml` broken, or missing, when the user adds a tile:** broken → nothing written and
   the error toast; missing → created with just the list (Task 1, Task 5 tests).
4. **A plugin disabled and enabled again, or updated to drop a widget:** its Home entries vanish
   from the strip, stay in the file, and come back (Task 2 test).
5. **Typing while Home is shown, then clearing the query:** Home tiles leave at the first typed
   character and come back with their cached frames at the empty query (Task 2 test).

### Task 2: The core: tiles by `TileKey`, Home instead of always tiles

**Files:**
- Modify: `crates/core/src/widget.rs` (`WidgetDecl`, `WidgetAnswer`, `WidgetContext`, new
  `TileKey`), `strip.rs`, `strip/order.rs`, `strip/render.rs`, `strip/schedule.rs`,
  `module.rs`, `host.rs`, `core.rs`, `effect.rs`, `testing.rs`, `lib.rs`
- Test: `crates/core/tests/widgets.rs` (rewrite the always-tile tests for Home),
  `crates/core/tests/core.rs` where needed

**Interfaces:**
- Consumes: Task 1's `Params`, `params()`, `HomeEntry`, `write_home`, `HomeWriteError`.
- Produces:
  - `WidgetDecl { id, title, sizes: Vec<WidgetSize> /* non-empty, first default */, params:
    Vec<String> /* declared keys */ }` with `fn default_size(&self) -> WidgetSize`.
  - `WidgetAnswer { widget: String, params: Params, size: Option<WidgetSize>, actions:
    Vec<Action> }` (the `payload` field is gone).
  - `WidgetContext.params: Params` replaces `payload`; `query` stays (search tiles only).
  - `pub enum Slot { Search, Home(u32) }` and `pub struct TileKey { pub widget: WidgetKey, pub
    params: Params, pub slot: Slot }` (Clone, Debug, PartialEq, Eq, Hash). For Home, the `u32` is
    the occurrence of an identical (widget, shown params) among the Home entries before it, so
    identical duplicates get 0, 1, 2…; a search tile is `Slot::Search`.
  - `StripTile { key: TileKey, title, size, frame, condition }`; `ConditionTile { actions,
    stale }` (no payload); `VisibleTile` and every tile-taking `Core` method take `&TileKey`:
    `send_widget_event`, `widget_actions`, `render_widget`, `stop_widget`, `widget_frame`,
    `widget_tick`'s visible list.
  - `Core::set_home(&mut self, home: Vec<HomeEntry>) -> bool` (changed);
    `Core::set_config_file(&mut self, path: PathBuf)`;
    `Core::add_to_home(&mut self, key: &TileKey) -> Result<(), HomeWriteError>` (appends the
    search tile's widget, its shown size and its params to the current list, calls `write_home`,
    and on success applies the new list at once).
  - `Core::home(&self) -> &[HomeEntry]`.
  - `Module::on_widget_event(&mut self, widget: &str, params: &Params, event: WidgetEvent)`,
    the render command carries `params`; new `Module::home(&mut self, tiles: Vec<HomeTile>)`
    with a default no-op, `pub struct HomeTile { pub widget: String, pub params: Params }`.
  - `Effect::ShowWidgets` removed; `Effect::RedrawWidget(id)` marks every tile of that widget.
- Rules (from the spec): at the empty query the strip is the Home tiles in list order; at a typed
  query only the search's tiles; the store needs to know whether the latest search's query is
  empty (pass it to `searched`). A Home entry shows only if its provider is registered and
  declares the widget; its size is the entry's if the decl offers it, else the default; its
  params are the entry's filtered to the declared keys. Home tiles keep their last frame across
  hides (the old instant open). After `set_home` and after a provider registers, each provider
  whose list of distinct `HomeTile`s (Home order, first occurrence wins) differs from the last
  one sent to it gets `Module::home`.
- Per-tile render state: one `WidgetState` per `TileKey` (two identical Home tiles render
  separately); stopping on late frames stays per tile; `stopped(provider)` lists widget ids
  with any stopped tile.
