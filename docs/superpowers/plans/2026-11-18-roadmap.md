# tomakast: plan roadmap for the first spec

Spec: `docs/superpowers/specs/2026-11-18-tomakast-core-design.md`.

The spec covers several subsystems, so it is split into sequential plans. Each plan produces working, testable software on its own.

| # | Plan | Outcome | Depends on |
|---|------|---------|------------|
| 1 | `2026-11-18-plan-1-foundation-linux.md`: core, launcher window and app search on Linux | A daemon on KDE/Wayland: a hotkey opens the launcher, which finds and launches apps and ranks them by usage. Plus a portable window-experiment binary for macOS and Windows | — |
| 2a | macOS: window (non-activating panel), hotkeys, `apps` for `.app` bundles, autostart | Plan 1 functionality on macOS, verified on the user's Mac | 1 |
| 2b-1 | `2026-11-18-plan-2b1-views.md`: views, navigation, action panel, dynamic sources (native modules), WASM tracer bullet, WIT 0.1 draft | Modules open list/grid/detail/form/scratchpad views on a stack, Ctrl/Cmd+K action panel, toasts; module calls off the UI thread; `apps` reveal/copy-path; demo module | 1 |
| 2b-2a | `2026-11-18-plan-2b2a-plugin-host.md`: WIT 0.1 pre-freeze edits, plugin host (wasmtime sync, out-of-process compile + cache, deadlines, limits, quotas, timers, http, open), hash-bound approval, hot reload, kitchen-sink test plugin, threat-model suite | A third-party WASM plugin loads from a folder without rebuilding, after approval; the spec's threat model is tested | 2b-1 |
| 2b-2b | `2026-11-19-plan-2b2b-sdk-calc-freeze.md`: guest SDK (Rust), `calc` (scratchpad + dynamic search + storage), WIT coverage test, WIT 0.1 and manifest freeze. **Done** (2026-11-19; acceptance: `docs/experiments/2026-11-plan2b2b-acceptance.md`) | Calculator works; WIT 0.1 frozen at the end | 2b-2a |
| 3 | Windows: window (tool window), `RegisterHotKey`, `apps` for the Start Menu, autostart | Same on Windows, verified on the user's machine | 1, 2a |

Plans 2a and 2b-1 can run in parallel, but both edit `crates/ui`: 2a owns `crates/ui/src/window.rs` (window kinds per OS), while 2b-1 must keep its `window.rs` changes to update plumbing and put views under `crates/ui/src/views/`. Merge one before the other's UI tasks start, or rebase carefully. 2b-2a and 2b-2b touch `plugin-host`, `plugin-api` and `plugins/*` and do not conflict with 2a; 2b-2a Tasks 1–3 change the core `Module` trait and the view model once, and native modules built in parallel rebase on that. Linux and macOS are both first-class platforms, and macOS must not lag behind Linux.

The spec requires a window experiment on Linux and macOS before the main UI work. Plan 1 therefore has a task that builds a portable experiment binary. The user runs it on the Mac and on Windows right after the skeleton is in place, before plans 2a and 3. If the Mac results are bad, the plan order is revisited.

**Status (2026-11-19): plan 2b-2b is done, and WIT 0.1 and the manifest format are frozen.** `crates/plugin-api/wit/since_v0.1.0/FROZEN` pins the hash of `plugin.wit`, and `crates/plugin-api/tests/freeze.rs` fails on any change to it or to the manifest keys. `FROZEN.md` next to it holds the policy (provisional until the user confirms it): relaxing a limit is a deliberate re-hash recorded there with its reason; tightening a limit or any change of shape needs a new `since_v0.2.0` folder. Plugin authors start from `docs/plugins/writing-a-plugin.md`.

The follow-up specs (dictation, clipboard, window management, converter, translator, caffeinate, notes, file search, sync, plugin manager) can now run in parallel. Some built-in modules (caffeinate, window management on Linux, dictation, file search) could start earlier, once plan 2b-1 Task 2 landed (it changes the module trait to async workers and adds dynamic sources). Per-feature wishes, open questions and the earliest point each one can start are in `docs/superpowers/backlog.md`.

## WIT 0.2 candidates

Contract gaps found by the final review of plan 2b-2b (G3–G13 in its report). None blocks a plugin today; each needs `since_v0.2.0`, so the first plugin that needs one should take it from here instead of rediscovering it.

- **G3. Storage:** no key listing, no batch (atomic) write, and no way to ask how much quota is left; a plugin keeps its own index, and one logical save is several writes against the 20/s rate.
- **G4. Scratchpad cursor:** `text-changed` carries no position and `action-chosen` names only the view, so "act on the current line" cannot be expressed.
- **G5. Scratchpad text from the plugin:** `update-view` cannot change the text and a re-push replaces the whole view (cursor, selection, revision), so a plugin cannot insert or rewrite text in place.
- **G6. Time zone and locale:** ~~time zone~~ done in place with the widgets edit (`locale.local-time-zone`, 2026-11-19); language and decimal separator stay open.
- **G7. Generated images:** ~~tiles~~ done for tiles in place with the widgets edit (`set-widget-image`: PNG, JPEG and SVG bytes a plugin fetched or made, drawn by image nodes and canvases, 2026-11-19); list, grid and command icons are still bundled files, theme names, emoji or colours only.
- **G8. List selection events:** no selection-changed event, so every row's detail must be sent up front.
- **G9. Notifications while hidden:** a toast shows only while the launcher is open; a timer plugin cannot tell the user anything otherwise.
- **G10. Toast kinds:** no warning or info kind; warnings are shown as errors.
- **G11. Clipboard and paste:** copy only, and no "paste into the frontmost application" effect.
- **G12. Secret preferences:** preferences are `text` or `bool`; an API key sits in the settings TOML in clear.
- **G13. Search ranking:** `search` items have no rank or match strength.
