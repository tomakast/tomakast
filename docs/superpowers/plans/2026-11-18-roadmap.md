# tomakast: plan roadmap for the first spec

Spec: `docs/superpowers/specs/2026-11-18-tomakast-core-design.md`.

The spec covers several subsystems, so it is split into sequential plans. Each plan produces working, testable software on its own.

| # | Plan | Outcome | Depends on |
|---|------|---------|------------|
| 1 | `2026-11-18-plan-1-foundation-linux.md`: core, launcher window and app search on Linux | A daemon on KDE/Wayland: a hotkey opens the launcher, which finds and launches apps and ranks them by usage. Plus a portable window-experiment binary for macOS and Windows | — |
| 2a | macOS: window (non-activating panel), hotkeys, `apps` for `.app` bundles, autostart | Plan 1 functionality on macOS, verified on the user's Mac | 1 |
| 2b | Plugin host and WASM: WIT 0.1, manifest, permissions, views, `calc` | A third-party WASM plugin loads from a folder without rebuilding. Views: list/grid/detail/form/action-panel/scratchpad/toast. Calculator scratchpad. The spec's threat model. Extra `apps` actions ("show in file manager", "copy path") via the action panel | 1 |
| 3 | Windows: window (tool window), `RegisterHotKey`, `apps` for the Start Menu, autostart | Same on Windows, verified on the user's machine | 1, 2a |

Plans 2a and 2b touch different crates: 2a touches `platform`, `ui` and `modules/apps`, while 2b touches `plugin-host`, `plugin-api`, `ui/views` and `plugins/calc`. So they can run in parallel. Linux and macOS are both first-class platforms, and macOS must not lag behind Linux.

The spec requires a window experiment on Linux and macOS before the main UI work. Plan 1 therefore has a task that builds a portable experiment binary. The user runs it on the Mac and on Windows right after the skeleton is in place, before plans 2a and 3. If the Mac results are bad, the plan order is revisited.

Once plan 2b is done, WIT 0.1 and the manifest format are frozen. From then on, the follow-up specs (dictation, clipboard, window management, converter, translator, caffeinate, notes, file search, sync, plugin manager) can run in parallel.
