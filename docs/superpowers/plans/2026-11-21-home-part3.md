# Home Part 3: the weather widgets — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The weather plugin gets ten widgets (`now`, `today`, and eight measures), each with
the `city` param, found by their words in the search, drawn from one forecast and one
air-quality request per place, and kept fresh for every place on Home, also while the
launcher is hidden.

**Architecture:** New pure modules in `plugins/weather/src/`: the answers (`api.rs`), the
plugin's 06–06 day (`day.rs`), the drawing kit (`ink.rs`, `chart.rs`), the tiles
(`today.rs`, `measures.rs`), the search words (`search.rs`), and one per-place store
(`feed.rs`, `location.rs`, `places.rs`) that replaces both `state.rs`'s `Weather` and
`search.rs`'s `Searched`. Each task adds tested, unwired code; Task 8 switches `lib.rs` and
the manifest over and deletes the old state.

**Tech Stack:** Rust 2024, the guest SDK (`tomakast-plugin`), WIT 0.1 canvas commands, native
tests in the plugin crate, host tests in `crates/plugin-host/tests/weather.rs`.

**Spec:** `docs/superpowers/specs/2026-11-21-home-widgets-design.md`, section "Part 3: The
weather widgets" (and "The contract" of Part 1 for the `home` event).

## Global Constraints

- Touch only `plugins/weather/**`, `crates/plugin-host/tests/weather.rs`, the weather section
  of `docs/plugins/writing-a-plugin.md` ("A smaller example: weather") and
  `docs/experiments/2026-11-quarter-weather-acceptance.md`. Another session edits the UI and
  core crates in parallel. If a task seems to need anything else, stop and report it.
- TDD: each step writes the failing test first and runs it to see it fail.
- No parser crates (the wasm stays small); JSON goes through `src/json.rs`.
- Every widget takes the param `city`; absent, blank or `auto` (any case, trimmed) means where
  the computer is.
- Sizes, first is the default: `now` = quarter, single; `today` = quarter, single, double;
  `humidity`, `wind`, `uv`, `pressure`, `precipitation`, `air-quality`, `pollen`,
  `daylight` = quarter, single.
- The plugin's day runs 06:00–06:00 in the place's own time. Morning 6–12, afternoon 12–18,
  evening 18–24, night 0–6 of the next date. Middle hours 9, 15, 21, 3.
- Sky severity: thunder > snow > rain > drizzle > fog > overcast > partly cloudy > clear.
- Refresh: a reading 15 minutes old is fetched again; failures back off 1, 2, 4, 8, then 15
  minutes. At most 4 requests in flight (the host's `MAX_CONCURRENT`).
- `fahrenheit` stays (°F and mph). New bool preference `mmhg` (pressure in mm Hg instead of
  hPa); display only, it never refetches.
- Copy is calm, English, sentence case. Failures never toast.
- Specs and plans in English. Commits carry no attribution lines. Never commit screenshots.
- Run things through `just` (`just check`) from the worktree; plugin tests are
  `CARGO_TARGET_DIR=target/plugins cargo test --manifest-path plugins/weather/Cargo.toml`;
  host tests are `cargo test -p tomakast-plugin-host --test weather` (they build the plugin's
  wasm themselves; check `crates/plugin-host/tests/support/harness.rs` `loaded_plugin`).
- Never start a launcher that grabs the keyboard. A headless daemon only, with its own
  `TOMAKAST_HOME` from `mktemp -d /tmp/tkw.XXXX` and `TOMAKAST_NO_KEYBOARD=1`; kill only
  your own processes.

## Decisions taken here (builder's calls and constraints found while planning)

1. **"Now" at a place comes from the answer, not the system clock.** A `Reading` keeps
   `current_time` (Open-Meteo's `current.time`, unix) and `fetched`; the place's time at
   `now` is `current_time + (now - fetched)`, its local clock adds `utc_offset`. Real
   readings are at most 15 minutes old, and tests with recorded fixtures stay deterministic.
2. **Requests.** Forecast, `timeformat=unixtime`:
   `current=temperature_2m,apparent_temperature,relative_humidity_2m,weather_code,is_day,wind_speed_10m`
   `&hourly=temperature_2m,apparent_temperature,relative_humidity_2m,dew_point_2m,precipitation_probability,precipitation,snowfall,weather_code,pressure_msl,wind_speed_10m,wind_direction_10m,wind_gusts_10m,uv_index`
   `&daily=temperature_2m_max,temperature_2m_min,sunrise,sunset,daylight_duration`
   `&timezone=auto&timeformat=unixtime&past_hours=24&forecast_hours=26&past_days=1&forecast_days=7`
   (+ `&temperature_unit=fahrenheit&wind_speed_unit=mph` for imperial). Probed live on
   2026-11-21: 50 hourly entries (24 back, 26 ahead, which always covers the 06–06 day:
   it starts at most 20 hours back and ends at most 24 ahead), 8 daily entries (yesterday
   to +6), about 5 KB. Air quality:
   `https://air-quality-api.open-meteo.com/v1/air-quality?latitude=…&longitude=…`
   `&hourly=european_aqi,european_aqi_pm2_5,european_aqi_pm10,european_aqi_nitrogen_dioxide,european_aqi_ozone,european_aqi_sulphur_dioxide,alder_pollen,birch_pollen,grass_pollen,mugwort_pollen,olive_pollen,ragweed_pollen`
   `&timezone=auto&timeformat=unixtime&past_hours=24&forecast_hours=26`, about 3.5 KB.
   Pollen outside Europe is `null`; in Europe out of season it is `0.0`.
3. **A measure's "value now" is the hourly value of the hour that holds the place's now**, so
   the value and the chart's dot agree. `now` keeps `current`.
4. **High and low of `today`** are the max and min of the 06–06 day's hourly temperatures
   (they agree with the columns). `now` single keeps the calendar day's daily max/min (the
   `days` entry whose local date is the place's date).
5. **Faded and muted icons are drawn as SVG on a canvas.** An icon node always takes the
   theme's text colour and nodes have no opacity (WIT 0.1); only canvas commands take
   `opacity`. The tile background is a translucent chip tint, so a veil over a column cannot
   match it either. The plugin therefore ships the Lucide SVGs it needs (copied from the
   launcher's own catalog, `gpui-kit-assets-0.10.0/assets/icons`, ISC; `LICENSE-LUCIDE`
   copied beside them), replaces `currentColor` with the theme's text colour, and draws them
   with `Draw::svg(..).opacity(..)`, sending the SVG in the frame (`FrameBuilder::image`).
   A bright icon stays an icon node. Faded text uses the theme's text colour with alpha.
   If Task 3's spike shows this cannot draw (the frame is refused or nothing shows in the
   host's frame check), stop and report; do not touch the WIT or the UI.
6. **Fading:** a part already over (or a past hour of a chart) is drawn at opacity 0.4; a
   muted icon (the part icons of the `today` quarter, the measure header icon, the icons of
   the `today` double's detail lines) at 0.6. The current part's icon is bright.
7. **Size from the context:** quarter when `width < 2 × height`, single when
   `width < 4 × height`, else double (quarter 173.5 × 120, single 355 × 120, double ≈ 718 ×
   120).
8. **Chart colours** (fixed, they read on both themes): line and rain bars `0x6EA8FEFF`;
   UV Low `0x6FCF6FFF`, Moderate `0xF2D64BFF`, High `0xF29A3BFF`, Very high `0xE5534BFF`,
   Extreme `0xB07CE8FF`; AQI (the European scale's colours) Good `0x50F0E6FF`, Fair
   `0x50CCAAFF`, Moderate `0xF0E641FF`, Poor `0xFF5050FF`, Very poor `0x960032FF`, Extremely
   poor `0x7D2181FF`; pollen bars `0xA6D96AFF`. The now line: 2 px dashes with 2 px gaps,
   1 px wide, theme text at 0.35; the dot: radius 3, theme text.
9. **Bands.** UV (rounded): Low < 3, Moderate 3–5, High 6–7, Very high 8–10, Extreme 11+.
   AQI: Good < 20, Fair 20–39, Moderate 40–59, Poor 60–79, Very poor 80–99, Extremely poor
   100+. Pollen (grains/m³, from the European pollen information scale, rounded to these
   steps): trees (alder, birch, olive) Low 1–9, Moderate 10–49, High 50–199, Very high 200+;
   grass Low 1–4, Moderate 5–19, High 20–49, Very high 50+; weeds (mugwort, ragweed) Low
   1–4, Moderate 5–14, High 15–49, Very high 50+; under 1 is none. Pressure trend over 3
   hours: ≥ +1 hPa rising, ≤ −1 hPa falling, else steady. Rain outlook: the first part, from
   the current one on, whose highest chance is ≥ 40%. "Rain is high" (blue chance in
   `today`): ≥ 50%.
10. **Within a severity class the higher WMO code is worse** (80 showers beats 61 rain).
    Classes: thunder 95–99; snow 71–77, 85, 86; rain 61–67, 80–82; drizzle 51–57; fog 45,
    48; overcast 3; partly cloudy 1, 2; clear 0. Morning and afternoon draw their sky by
    day, evening and night by night.
11. **Storage, per place:** keys `forecast:<key>` and `air:<key>`, `<key>` being
    `cities::key` of the tile's `city` for a city and `@here` for the location; a value is
    `units=…\nfetched=…\nname=…\nlat=…\nlon=…\n` then `body=` and the raw answer on one line.
    Restoring reparses the body, so there is one parser. Keys over 240 bytes are not stored.
    The old key `last` is removed at `init`.
12. **What is refreshed:** every place a Home tile names (from the `home` event), the
    location when a tile without a city is on Home or is the search's tile, and the search's
    place once the query rests 300 ms. Air only for a place with an `air-quality` or
    `pollen` tile among those. A place the `home` event drops is forgotten (memory and
    storage) unless the search tile or the location still names it; places only searched
    stay in a cache trimmed past 32, which never trims a wanted place.
13. **A refused `http::fetch` at the concurrency cap is not a failure**: it stays due for the
    next tick, with no backoff and no warning. Other refusals are failures, as now.
14. **The location is asked only while a tile without a city is on Home or is the search's
    tile.** With an empty Home and no search tile the plugin sends nothing.
15. **Search tiles show the widget's default size.** `weather today` shows `today` as a
    quarter, like a Home tile added without a size.

## Review Focus

- **The hours do not cover the day** (an old stored reading, an answer without `hourly`, a
  day boundary between refreshes): `today` and the measures draw what they have, "—" where a
  part or the value is unknown, and never panic or index out of range. Owned by Task 2
  (`parts` and `series` with gaps) and Tasks 4–5 (frames with an empty `hours`).
- **A Home place dropped and re-added, or the same city typed two ways** (`Berlin` and
  `berlin, de`): one spot, one request, and the forgotten one's storage removed exactly
  once. Owned by Task 7 (`a_place_named_two_ways_is_one_spot`,
  `a_dropped_place_is_forgotten_and_its_storage_removed`).
- **Many Home places at once** (five cities × two requests): never more than 4 in flight, the
  rest started on later ticks without counting failures. Owned by Task 7
  (`at_most_four_requests_wait_and_the_rest_wait_their_turn`) and Task 8 (host test).
- **Units or `mmhg` changed while tiles show**: units refetch forecasts (air kept); `mmhg`
  redraws only. Owned by Task 7 (`new_units_forget_forecasts_not_air`) and Task 8
  (`mmhg_shows_pressure_in_mm_hg_without_a_request`).
- **A search word that is also a city's prefix while typing** (`wind i`, `погода в`,
  `uv index`, `air`): no tile, or the right widget, never the wrong city lookup. Owned by
  Task 6 (`typing_a_word_shows_nothing_until_it_names_a_city`).

### Task 2: The plugin's day

**Files:**
- Create: `plugins/weather/src/day.rs` (add `pub mod day;` to `lib.rs`)

**Interfaces:**
- Consumes: `api::{Reading, Hour, Day, Air, AirHour, POLLENS, Units}`.
- Produces (`day.rs`), all pure:
  - `pub fn place_now(reading: &Reading, now: i64) -> i64` = `current_time + (now - fetched)`.
  - `pub fn day_start(at: i64, utc_offset: i64) -> i64`: the unix time of the local 06:00
    at or before `at`.
  - `pub enum Part { Morning, Afternoon, Evening, Night }` with `pub const ALL: [Part; 4]`,
    `pub fn name(self) -> &'static str` ("Morning", "Afternoon", "Evening", "Night"),
    `pub fn icon(self) -> &'static str` ("sunrise", "sun", "sunset", "moon").
  - `pub enum When { Past, Now, Ahead }`
  - `pub struct PartSummary { pub part: Part, pub when: When, pub temperature, feels_like,
    wind: Option<f64>, pub code: Option<u16>, pub rain_chance: Option<f64>, pub rain:
    Option<f64> }` — temperature/feels/wind of the middle hour; code the worst; chance the
    highest; rain the sum (None when no hour of the part has a value).
  - `pub fn parts(reading: &Reading, now: i64) -> [PartSummary; 4]`
  - `pub fn severity(code: u16) -> (u8, u16)` (class rank, code) per Decision 10.
  - `pub fn range(reading: &Reading, now: i64) -> Option<(f64, f64)>` (high, low of the day's
    hours).
  - `pub struct Series { pub values: [Option<f64>; 24], pub now: f32 }` — the day's hours
    from 06 to 05, `now` the place's now as fractional hours since the day's start (0..24).
  - `pub fn series(reading: &Reading, now: i64, pick: fn(&Hour) -> Option<f64>) -> Series`
  - `pub fn air_series(air: &Air, reading: &Reading, now: i64, pick: fn(&AirHour) ->
    Option<f64>) -> Series` (the day from the forecast's place time; hours by `at`).
  - `pub fn hour_now<'a>(reading: &'a Reading, now: i64) -> Option<&'a Hour>` and
    `pub fn air_now<'a>(air: &'a Air, reading: &Reading, now: i64) -> Option<&'a AirHour>`.
  - `pub enum Level { .. }` is not needed; levels are `(&'static str, u32 colour)`:
    `pub fn uv_level(uv: f64) -> (&'static str, u32)`, `pub fn aqi_level(aqi: f64) ->
    (&'static str, u32)`, `pub fn pollen_level(pollen: usize, grains: f64) ->
    Option<&'static str>` (None under 1).
  - `pub fn uv_until(reading: &Reading, now: i64) -> Option<String>`: "till 15:00" when the
    current hour is ≥ 3 (the first later hour under 3), "from 11:00" when a later hour of the
    day is ≥ 3, else None.
  - `pub enum Trend { Rising, Falling, Steady }`; `pub fn pressure_trend(reading: &Reading,
    now: i64) -> Option<Trend>` (current hour minus 3 hours earlier, Decision 9).
  - `pub fn compass(from_degrees: f64) -> (&'static str, &'static str)`: the arrow it blows
    to and the point it blows from, 8 points: 266° → ("→", "W"); 45° → ("↙", "NE").
  - `pub fn rain_outlook(reading: &Reading, now: i64) -> Option<String>`: "70% now" for the
    current part, "40% after 18:00" for a later one, None without one (Decision 9).
  - `pub fn strongest_pollen(air: &Air, reading: &Reading, now: i64) -> Vec<(usize, f64)>`:
    pollens of the current hour with ≥ 1 grain, strongest level first, then grains.
  - `pub fn daylight(reading: &Reading, now: i64) -> Option<DaylightInfo>` with `pub struct
    DaylightInfo { pub length: f64, pub sunrise: i64, pub sunset: i64, pub change: f64,
    pub week: Vec<f64> }` — the `days` entry of the plugin day's date (the date of
    `day_start`), its next day for `change` (seconds), and up to 7 lengths from it on.
  - `pub fn clock(at: i64, utc_offset: i64) -> String` ("07:38").
  - `pub fn length(secs: f64) -> String` ("8 h 27 min"); `pub fn signed_minutes(secs: f64) ->
    String` ("−3 min", "+2 min", "±0 min", true minus sign).
